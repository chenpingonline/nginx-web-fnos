# 使用指南

[返回首页](../README.md) · [完整功能清单](features.md) · [DNS 服务商配置](dns-providers.md)

适用于 0.2.0。本文从创建第一条代理开始，说明 IPv6、HTTPS、分组和日常排查。示例中的域名与地址需要替换为自己的配置。

## 1. 先分清入口与后端

```text
浏览器 → https://music.example.com:9560 → nginx-web → http://192.168.1.22:2330
         域名、监听类型、端口、证书                    后端协议、主机、端口
```

- **入口**是客户端访问的地址；域名解析、监听类型和防火墙必须与这条访问路径匹配。
- **后端**是 NAS 能连接的服务。入口使用 HTTPS，后端可以使用 HTTP；入口使用 IPv6，后端也可以使用 IPv4。
- **管理页面**通过 fnOS 桌面打开，与代理入口不是同一个地址。
- **已生效 / 配置已同步**表示配置已应用，不代表后端服务或外网连接已通过健康检查。

监听端口只能使用 **1024–65535**，并且不能被其他程序占用。下面使用 `9080` 演示 HTTP，`9560` 演示 HTTPS，这两个端口都需要按自己的环境检查。

## 2. 创建第一条 HTTP 代理

先确认 NAS 能访问 `http://192.168.1.22:2330`，然后打开 **HTTP(S) 代理 → 添加代理规则**：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 所属分组 | 未分组 | 首次可不创建分组 |
| 规则名称 | music | 用于管理时识别 |
| 访问域名 / IP | `music.example.com` | 不填 `http://`，不带端口或路径 |
| 监听类型 | IPv4 | 使用 IPv6 时按下一节调整 |
| 监听端口 | `9080` | 浏览器访问时也要带此端口 |
| 入口协议 | 不启用 HTTPS | 先验证 HTTP 链路 |
| 后端服务组 | 单个后端服务 | 多节点需求再使用服务组 |
| 后端服务协议 | HTTP | 与后端实际协议一致 |
| 目标主机 | `192.168.1.22` | 填后端地址 |
| 目标端口 | `2330` | 填后端实际服务端口 |

保存并应用配置，确认 Nginx 正在运行。将 `music.example.com` 解析到客户端可访问的 NAS 地址，再访问 `http://music.example.com:9080`。代理列表的入口后可复制地址或直接跳转，后端地址也可复制。

目标主机支持粘贴 `http://192.168.1.22:2330`，自动拆成协议、主机和端口；手动输入后移开焦点也会识别。支持 `主机:端口` 和 `[IPv6地址]:端口`。带非根路径、查询参数、片段或用户名密码的 URL 不会自动拆分，路径转发应在 Location 中配置。

## 3. 配置 IPv6 或双栈访问

| 客户端访问方式 | DNS 记录 | HTTP(S) 监听类型 |
| --- | --- | --- |
| IPv4 | A 指向可达的 IPv4 地址 | IPv4 或双栈 |
| IPv6 | AAAA 指向 NAS 可达的 IPv6 地址 | IPv6 或双栈 |
| 两者都需要 | 分别配置 A 和 AAAA | 同时勾选 IPv4、IPv6 |

外网 IPv4 访问通常还需要路由器端口映射，前提是具备可用的公网入口。IPv6 访问需要客户端支持 IPv6，并放行路由器和 NAS 防火墙对应的入站端口。仅添加 DNS 记录不会自动开放端口，也不会建立端口映射。

`0.0.0.0:9560` 表示监听所有 IPv4 网卡；`[::]:9560` 表示监听所有 IPv6 网卡。这是监听地址，浏览器应使用自己的域名或可达 IP。

旧配置未指定监听类型时保持 IPv4。修改分组为 IPv6 后，已有规则还需勾选继承分组的 **监听类型**，或直接修改规则自己的监听类型，保存并应用后才会生效。

## 4. 申请并使用 HTTPS 证书

### 自动申请

1. 打开 **SSL/TLS 证书 → 导入证书**，选择 **ACME 自动申请**。
2. 填写名称、邮箱、证书机构和签发域名。正式访问选择正式环境；测试环境证书不受浏览器信任。
3. 选择管理该域名 DNS 的服务商，按表单填写凭据，确认其有权完成 DNS 验证。具体字段见 [DNS 服务商配置](dns-providers.md)。
4. 阅读并同意所选 CA 服务条款，点击 **开始申请**。
5. 等待后台任务签发成功；失败时查看任务详情，按错误信息检查凭据权限、DNS 验证记录和网络连接。
6. 编辑代理规则，开启 HTTPS，选择已签发证书，设置监听端口（例如 `9560`），保存并应用。
7. 访问 `https://music.example.com:9560`，检查浏览器显示的证书域名和有效期。

DNS-01 通过 DNS 记录证明域名控制权，不要求通过本应用监听 80/443 完成验证。签发成功不等于业务域名已正确配置 A/AAAA 或业务端口已放行。

### 域名覆盖范围

| 证书包含的域名 | 能覆盖 | 不能覆盖 |
| --- | --- | --- |
| `example.com` | `example.com` | `music.example.com` |
| `*.example.com` | `music.example.com`、`nas.example.com` | `example.com`、`a.b.example.com` |
| `example.com` 和 `*.example.com` | 根域名及一级子域名 | `a.b.example.com` |

同时使用根域名和一级子域名时，在签发域名中同时填写 `example.com` 和 `*.example.com`。证书名称只是管理标签，应以证书详情中的 **SAN 域名**为准。

### 修改域名并重新签发

在证书列表点击 **修改**，编辑域名，点击 **修改并重新签发**。系统复用原证书机构、DNS 凭据和账户，并启用自动续期。成功后沿用原证书 ID，已有代理规则无需重新选择证书；失败时继续使用旧证书。任务提交成功后仍需等待签发和部署完成。

未关联 ACME 任务的手动导入证书无法直接重新签发，需要通过“导入证书”重新填写 ACME 申请信息。若生成了另一张证书，应在规则或继承的分组中选择新证书并应用。

### 手动导入

支持上传 PEM 证书链和匹配的私钥、粘贴 PEM，或从服务器绝对路径导入。路径导入会复制文件，源文件以后更新不会自动同步，需要重新导入。

## 5. 用分组管理多个入口

例如 `music.example.com`、`panel.example.com` 共用 HTTPS、9560、IPv6 和同一张通配符证书，可以先创建分组并设置这些默认值，再在分组中添加规则。

- 新规则可继承监听类型、协议、端口、证书和 HTTP/2；取消某项继承后可单独配置。
- 已有规则移入其他分组会保留原配置，需要勾选相应继承项才使用分组默认值。
- 修改分组只更新继承该项的规则；删除分组后，规则保留配置并移至未分组。
- 页面顶部按分组、协议、状态或关键字筛选；分组标题前可展开、收起规则。
- 分组保存会应用全部待生效草稿，操作前留意其他尚未应用的修改。

多个域名可以共用监听端口，由域名区分规则。访问域名字段应填 `panel.example.com`，不能填 `panel.example.com:9560`；端口单独填写。

## 6. TCP/UDP 转发

打开 **TCP/UDP 代理 → 添加 TCP/UDP 规则**。普通 TCP 转发示例：

| 字段 | 示例 |
| --- | --- |
| 名称 / 协议 | ssh / TCP |
| 监听地址 / 端口 | `0.0.0.0` / `2222` |
| 目标主机 / 端口 | `192.168.1.22` / `22` |
| TLS | 关闭 |

保存并应用后，SSH 客户端连接 NAS 可达地址的 `2222` 端口。UDP 服务需选择 UDP，并在防火墙或端口映射中放行 UDP。

TCP 的 **TLS 终止**由本应用提供证书；**TLS SNI 透传**将 TLS 流量交给后端，由后端提供证书。普通 SSH 等非 TLS 服务无需开启 TLS。PROXY Protocol 只有上下游明确支持并已匹配配置时才启用。

## 7. 日志、配置与备份

- **运行日志**：选择日志类型与最近行数；搜索只针对当前加载的日志，搜索期间暂停自动刷新。输入关键字后显示匹配数量和上一个/下一个按钮；清空搜索后恢复正常刷新。默认不自动换行，长行可用底部横向滚动条查看，勾选“自动换行”后折行显示。
- **Nginx 配置**：主配置单独展示，其余按系统配置、HTTP(S) 代理、TCP/UDP 代理下拉选择；可查看、复制和校验生成配置，不能直接编辑原始指令。
- **备份与恢复**：升级前导出 JSON。恢复备份或配置历史后先检查草稿，再应用。备份包含证书私钥，应妥善保管；不包含 ACME 账户、DNS 凭据和自动续期任务，迁移到新设备需要重新配置续期。外部文件需单独迁移。

## 8. 常见故障排查

先按 **后端可达 → DNS → 监听与防火墙 → 证书 → HTTP 响应** 的顺序检查。

| 现象 | 检查方向 |
| --- | --- |
| 连接超时、被拒绝或 `ERR_CONNECTION_CLOSED` | 确认访问协议和端口、Nginx 运行状态、A/AAAA 指向、监听类型、防火墙及端口映射；这些提示本身不能确定唯一原因 |
| Lucky 能访问，本应用不能 | 对照两个程序的监听类型、端口、TLS、证书和防火墙配置；切换程序时检查旧进程是否仍占用端口 |
| IPv4 可以、IPv6 不可以 | 检查客户端 IPv6、AAAA 地址、规则实际是否继承 IPv6、IPv6 入站防火墙 |
| 配置已生效但没有请求统计 | 请求可能没有到达本应用，也可能尚未完成或访问日志关闭；结合访问日志判断 |
| 浏览器显示“不安全” | 检查浏览器实际收到的证书 SAN、有效期、签发机构和证书链，确认不是测试证书、自签证书或旧证书 |
| 修改证书后仍“不安全” | 确认重新签发及部署成功、规则选择正确证书、DNS 指向正确设备；核对实际证书后再用新窗口重试，不要直接归因于缓存 |
| 502 / 504 | 从 NAS 检查后端地址、端口、HTTP/HTTPS 协议及服务状态，并查看 Nginx 错误日志；根据原因检查超时设置 |
| 打开了其他站点或 404 | 核对域名、端口、规则启用状态和路径匹配，再判断响应来自代理还是后端 |

HTTPS 入口转到 HTTP 后端本身不会造成浏览器证书警告。如果页面还引用了 HTTP 资源，需要另外检查混合内容。

向项目反馈问题时，请提供应用版本、fnOS 版本、CPU 架构、访问方式（内网/外网、IPv4/IPv6）、浏览器错误或 HTTP 状态码，以及相关日志。不要附上私钥、DNS 凭据或完整备份文件。
