# nginx-web 使用说明

[返回项目首页](../README.md) · [完整功能清单](features.md) · [DNS 服务商配置](dns-providers.md)

本文适用于 nginx-web **0.2.31**，面向通过 fnOS 应用中心安装和使用本软件的管理员。文中的域名、IP 地址和端口均为示例，请替换为自己的实际配置。

nginx-web 是一套独立运行的 Nginx 可视化管理应用。它不会读取、修改或重启飞牛系统自带的 Nginx，而是使用安装包内置的 Nginx、独立配置目录和独立日志目录完成 HTTP/HTTPS 反向代理及 TCP/UDP 转发。

## 1. 使用前准备

### 1.1 运行条件

- fnOS 1.1.3100 或更新版本。
- 使用 fnOS 管理员账号安装并打开管理界面。
- 根据设备 CPU 架构选择安装包：Intel/AMD 64 位选择 `x86_64.fpk`，ARM 64 位选择 `arm64.fpk`。
- NAS 能访问需要代理的容器、NAS 应用或局域网服务。
- 客户端到 NAS 的目标端口已在防火墙、路由器或安全策略中放行。

安装和运行 FPK 不需要 Docker、Go、Node.js 或系统 Nginx。Docker 只用于从源码编译内置 Nginx，不是运行依赖。

### 1.2 端口与权限限制

nginx-web 的管理服务和内置 Nginx 均以普通 `nginx-web` package 用户运行，不申请 root 权限。因此，通过结构化表单创建的 HTTP/HTTPS 和 TCP/UDP 入口只能监听 **1024–65535**，并且端口不能已被其他程序占用。

如需对外提供标准 80/443 端口，请先阅读[第 7 节](#7-使用-80-和-443-端口)。

### 1.3 建议提前准备

- 转发服务地址，例如 `192.168.1.22:2330`。
- 一个未被占用的高位端口，例如 HTTP 使用 `9080`、HTTPS 使用 `9443`。
- 如需域名访问，准备可修改的 DNS 解析。
- 如需 HTTPS，准备 PEM 证书和私钥，或者具有 DNS 记录修改权限的 API 凭据。

## 2. 安装、升级与卸载

### 2.1 安装

1. 从项目 Release 下载与 NAS 架构匹配的 FPK。
2. 如 Release 同时提供 `SHA256SUMS.txt`，建议先校验安装包摘要。
3. 打开 **fnOS → 应用中心 → 手动安装**。
4. 选择 FPK，确认安装。
5. 安装完成后，从 fnOS 桌面打开 **nginx-web**。

管理页面由 fnOS 统一网关打开，不需要手工配置访问端口，也不要把管理入口和后续创建的代理入口混为一谈。

### 2.2 升级

1. 进入 **备份与恢复**，下载一份最新 JSON 备份。
2. 下载正确架构的新版 FPK。
3. 在 fnOS 中通过手动安装方式覆盖升级。
4. 升级后打开总览，检查版本、Nginx 状态和规则状态。
5. 若页面提示统计入口尚未启用，请先确认没有不希望应用的草稿，再执行一次 **保存并应用**。

升级不会把 x86_64 安装包转换为 ARM64 安装包。跨设备迁移请使用备份恢复，并单独处理 ACME 续期任务和外部文件。

### 2.3 卸载前

卸载前至少完成以下操作：

1. 导出配置备份。
2. 另行保存需要保留的外部密码文件、客户端 CA、静态目录或其他自定义配置依赖文件。
3. 确认已保存后再卸载应用。

## 3. 认识管理入口、代理入口和后端

```text
管理配置：fnOS 桌面 → fnOS 统一网关 → nginx-web 管理服务

业务访问：浏览器 → https://music.example.com:9443 → 内置 Nginx
                                                    ↓
                                      http://192.168.1.22:2330
```

- **管理入口**：从 fnOS 桌面打开的 nginx-web 页面，只用于管理配置。
- **代理入口**：客户端实际访问的域名/IP、协议和监听端口。
- **转发服务**：由内置 Nginx 转发到的目标应用或设备。
- **草稿配置**：已保存到 nginx-web，但尚未成为 Nginx 当前运行配置的修改。
- **已应用配置**：已经过校验并交给内置 Nginx 使用的配置。

入口和后端可以使用不同协议。例如，客户端使用 HTTPS，后端仍可使用 HTTP；客户端通过 IPv6 访问，后端也可以是 IPv4 地址。

“已生效”或“配置已同步”只说明配置已经应用，不等于 DNS、外网端口映射、转发服务或防火墙一定正常。

## 4. 创建第一条 HTTP 代理

以下示例把 `http://music.example.com:9080` 转发到 `http://192.168.1.22:2330`。

### 4.1 验证后端

先确认 NAS 自身可以访问：

```text
http://192.168.1.22:2330
```

如果 NAS 无法访问后端，应先修复转发服务、容器网络或局域网路由。反向代理不能修复一个本身不可达的后端。

### 4.2 创建规则

打开 **HTTP(S) 代理 → 添加代理规则**，填写：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 所属分组 | 未分组 | 首次使用可暂不创建分组 |
| 规则名称 | 音乐服务 | 仅用于管理识别 |
| 访问域名 / IP | `music.example.com` | 不填写协议、端口或路径 |
| 监听类型 | IPv4 | 需要 IPv6 时参考第 6 节 |
| 监听端口 | `9080` | 客户端访问时必须带上此端口 |
| 入口协议 | HTTP | 首次建议先验证 HTTP 链路 |
| 后端类型 | 单节点服务 | 多节点时改用转发服务组 |
| 后端协议 | HTTP | 必须与后端实际协议一致 |
| 目标主机 | `192.168.1.22` | 不带路径 |
| 目标端口 | `2330` | 后端实际监听端口 |

目标主机支持粘贴 `http://192.168.1.22:2330`、`主机:端口` 或 `[IPv6地址]:端口`，页面会尝试拆分协议、主机和端口。带业务路径、查询参数、片段或用户名密码的 URL 不会自动拆分；路径转发应在 Location 中配置。

### 4.3 应用并访问

1. 保存规则。
2. 点击页面顶部的 **校验配置**；校验通过后点击 **保存并应用**。
3. 在总览确认内置 Nginx 正在运行，规则状态为已生效。
4. 将 `music.example.com` 的 A 记录解析到客户端可访问的 NAS IPv4 地址。
5. 在浏览器访问 `http://music.example.com:9080`。

同一端口可以按不同域名承载多条 HTTP/HTTPS 规则，但同一个监听范围内不能重复配置相同域名、协议冲突或多条默认站点。域名字段填写 `music.example.com`，不要填写 `music.example.com:9080`。

## 5. 配置 HTTPS 和证书

证书可以手动导入，也可以通过 ACME DNS-01 自动申请。

### 5.1 手动导入

打开 **SSL/TLS 证书 → 导入证书**，选择以下任一种方式：

- 上传 PEM 证书链和匹配的私钥文件。
- 粘贴 PEM 证书链和私钥内容。
- 从服务器绝对路径导入。源文件必须位于已在飞牛应用设置中授权给 nginx-web 的目录内。

路径导入会把文件复制进应用私有目录。源路径中的证书日后发生变化时，应用内副本不会自动同步，需要重新导入。

### 5.2 ACME 自动申请

1. 打开 **SSL/TLS 证书 → 导入证书 → ACME 自动申请**。
2. 填写证书名称、联系邮箱、证书机构和签发域名。
3. 选择域名实际使用的 DNS 服务商。
4. 按表单填写 DNS API 凭据，确保凭据拥有目标 Zone 的读取和 DNS 记录修改权限。
5. 阅读并同意所选 CA 的服务条款。
6. 点击 **开始申请**，在任务列表等待签发完成。
7. 签发成功后编辑代理规则，开启 HTTPS，选择该证书和 HTTPS 监听端口，例如 `9443`。
8. 保存并应用后访问 `https://music.example.com:9443`。

支持的 DNS 服务商和字段说明见 [DNS 服务商配置](dns-providers.md)。DNS-01 不要求应用监听 80/443，但 DNS API 必须可用，NAS 也需要能够访问 ACME 和 DNS 服务商接口。

### 5.3 证书域名覆盖

| 证书 SAN | 可以覆盖 | 不能覆盖 |
| --- | --- | --- |
| `example.com` | `example.com` | `music.example.com` |
| `*.example.com` | `music.example.com` | `example.com`、`a.b.example.com` |
| `example.com` 和 `*.example.com` | 根域名及一级子域名 | `a.b.example.com` |

证书名称只是管理标签，应以证书详情显示的 SAN 为准。

### 5.4 自动续期与重新签发

- ACME 任务会定期检查续期时间，失败后按退避策略重试。
- 自动续期沿用证书 ID；成功部署后，引用该证书的规则不需要重新选择。
- Nginx 运行时会校验并平滑重载；如果 Nginx 已停止，续期只保存证书，不会自动启动 Nginx。
- 在证书列表点击 **修改**，可以调整已关联 ACME 任务的域名并重新签发；失败时继续保留旧证书。
- 手动导入且没有关联 ACME 任务的证书不能直接自动续期，需要重新导入或创建 ACME 任务。

### 5.5 HTTPS 常见提醒

- 签发成功不等于域名 A/AAAA 记录已指向正确 NAS。
- HTTPS 入口转发到 HTTP 后端是正常用法，不会单独造成证书警告。
- 页面内若引用了 HTTP 资源，浏览器可能报告混合内容，需要修改后端应用生成的资源地址。
- 删除证书前必须先解除 HTTP 或 Stream 规则引用。

## 6. 使用 IPv6 或双栈

HTTP(S) 规则和分组支持 IPv4、IPv6、双栈三种监听类型。

| 客户端访问方式 | DNS 配置 | 监听类型 |
| --- | --- | --- |
| IPv4 | A 记录指向可达 IPv4 地址 | IPv4 或双栈 |
| IPv6 | AAAA 记录指向可达 IPv6 地址 | IPv6 或双栈 |
| IPv4 与 IPv6 | 同时配置 A 和 AAAA | 双栈 |

- `0.0.0.0:9443` 表示监听所有 IPv4 网卡。
- `[::]:9443` 表示监听所有 IPv6 网卡。
- 浏览器应使用自己的域名或可达 IP，不要把 `0.0.0.0` 或 `[::]` 当作访问地址。
- 仅创建 AAAA 记录不会自动放行 IPv6 防火墙。
- 外网 IPv4 通常还需要路由器端口映射，并且需要可用的公网入口。
- IPv6 入口可以转发到 IPv4 后端。

旧配置未指定监听类型时继续按 IPv4 处理。修改分组监听类型后，已有规则只有在继承该字段时才会跟随改变。

## 7. 使用 80 和 443 端口

当前版本以普通用户运行，结构化表单不允许直接监听 80/443。推荐保持应用监听高位端口，再在入口设备进行映射：

```text
公网或局域网 80   → NAS 9080 → nginx-web HTTP 规则
公网或局域网 443  → NAS 9443 → nginx-web HTTPS 规则
```

可采用的入口设备包括路由器端口映射、具备权限隔离的前置反向代理或其他网关。映射协议必须一致：TCP 80/443 映射到对应 TCP 高位端口，UDP 服务则需要单独配置 UDP 映射。

不要仅在自定义配置中写入 `listen 80` 或 `listen 443`。普通 package 用户通常会因权限不足而启动失败。让整个应用以 root 运行会同时扩大管理服务、自定义配置、证书处理和内置 Nginx 的权限范围，不属于当前版本的安全设计。

## 8. 规则分组、转发服务组和限流

### 8.1 HTTP(S) 规则分组

当多个域名共用监听类型、HTTP/HTTPS、端口、证书或 HTTP/2 设置时，可以先建立分组。

- 新规则可以继承分组默认值。
- 每个继承项都可以单独取消，再设置规则自己的值。
- 把已有规则移入其他分组时会保留原值，不会自动覆盖；需要勾选对应继承项。
- 修改分组只影响仍在继承该字段的规则。
- 删除分组后，规则保留当前值并移动到“未分组”。
- 分组保存会应用全部待生效草稿，操作前应检查是否还有其他未完成修改。

### 8.2 转发服务组

需要负载均衡或多个后端节点时，先在 **转发服务组** 创建 HTTP 或 Stream 服务组，再在规则中选择。

每个节点可配置主机、端口、权重、最大失败次数、故障恢复时间、备用或停用状态。HTTP 服务组支持 Round Robin、Least Connections、IP Hash、Hash 和 Random Two Least Connections；Stream 服务组不提供 IP Hash。

这里的失败次数和恢复时间属于 Nginx 请求过程中的被动失败处理，不等同于独立的主动健康检查。删除服务组前需要先解除规则引用。

### 8.3 限流策略

在 **限流策略** 中创建可复用策略，然后在 HTTP(S) 规则中选择。可配置：

- 单个客户端 IP 的平均请求速率。
- 突发容量，以及突发请求立即处理或排队。
- 单个客户端 IP 的并发连接数。
- 单个响应的下载速度。

同一策略绑定到多条规则时，额度仍按规则独立计算。排队、下载限速与真正被拒绝的请求是不同事件，可在请求分析的限流视图中分别查看。

## 9. TCP/UDP 转发

打开 **TCP/UDP 代理 → 添加 TCP/UDP 规则**。以下示例把 NAS 的 TCP 2222 端口转发到内网 SSH 服务：

| 字段 | 示例 |
| --- | --- |
| 名称 | SSH 转发 |
| 协议 | TCP |
| 监听地址 | `0.0.0.0` |
| 监听端口 | `2222` |
| 后端类型 | 单节点服务 |
| 目标主机 | `192.168.1.22` |
| 目标端口 | `22` |
| TLS 模式 | 关闭 |

保存并应用后，客户端连接 NAS 可达地址的 2222 端口。UDP 服务必须选择 UDP，并在防火墙和端口映射中单独放行 UDP。

TCP 规则还支持：

- **TLS 终止**：由 nginx-web 提供证书，后端接收解密后的 TCP 流量。
- **TLS SNI 透传**：不在 nginx-web 解密，按客户端 SNI 将流量交给不同后端，证书由后端提供。
- **PROXY Protocol**：向后端传递原始客户端信息，只有上下游明确支持并且配置一致时才启用。
- **访问控制**：按 IP/CIDR 允许或拒绝。
- **单 IP 连接限制**：限制同时连接数。
- **Stream 转发服务组**：复用多个 TCP/UDP 节点。

SSH、普通数据库等非 TLS 服务不要误开 TLS。SNI 分流只适用于带 SNI 的 TLS 流量。

## 10. 高级 HTTP 功能

HTTP(S) 规则的根路径和附加 Location 可以分别选择前缀、精确或正则匹配，并使用不同处理方式，包括：

- HTTP/HTTPS 反向代理、gRPC、FastCGI、uWSGI、SCGI、Memcached。
- 静态文件、固定响应、跳转和 Stub Status。
- WebSocket、SSE/流式传输、请求体大小及连接/读取/发送超时。
- Rewrite、请求/响应 Header、代理缓存、Gzip、内容替换和镜像请求。
- IP/CIDR 访问控制、Basic Auth、Auth Request、Secure Link、Referer 防盗链和有限 WebDAV。

使用高级选项时注意：

- WebSocket 后端需要开启对应选项；SSE 和长响应应启用流式传输，并合理增加读取超时。
- 静态文件、密码文件、客户端 CA 等路径必须在 NAS 上真实存在，并先在飞牛应用设置中加入授权目录。应用会解析符号链接并拒绝授权目录外、包含上级目录跳转或类型不符的路径；WebDAV 目录还必须允许 `nginx-web` 用户写入。
- 正则 Location、Rewrite 和缓存 Key 中的变量应使用 Nginx 支持的语法。
- 缓存仅清理 nginx-web 自己的代理缓存，不影响后端应用缓存或浏览器缓存。
- 不确定高级指令效果时，先备份，再使用校验功能，不要直接在生产入口试错。

完整配置能力见[功能与使用说明](features.md)。

## 11. 总览、请求分析与日志

### 11.1 总览

总览展示内置 Nginx 状态、运行时长、工作进程、活动连接、请求/响应速率、完成请求、错误率、趋势及规则状态。

常见规则状态：

- **已生效**：当前运行配置中存在并启用。
- **待应用**：草稿与当前运行配置不同。
- **已停用**：规则已保存但未启用。
- **待删除**：草稿已删除，但当前运行配置仍保留，应用后才真正移除。

页面关闭后管理服务仍会继续采样。统计按分钟汇总，最多保留最近 30 天；没有采集到的历史保持为空，不会补成零。

### 11.2 HTTP/HTTPS 请求分析

在 **请求分析** 中可按规则和时间范围查看：

- 已完成请求数量、4xx、5xx 和总错误率。
- 请求与错误趋势、受影响规则和样本。
- 限流拦截、延迟处理、触发策略及排行。

HTTP 请求在结束后才写入日志。尚未结束的长下载、WebSocket 和 SSE 不会提前计入完成请求与错误率。关闭访问日志会停止规则级日志统计，但 Nginx 状态采样仍可能继续。

限流样本数量不是完整拦截总数；限流事件与 HTTP 错误可能重叠，不能简单相加。

### 11.3 TCP/UDP 会话分析

请求分析页面可切换到 TCP/UDP，查看已结束会话、异常会话、并发拦截、流量和平均会话时长。

- 需要为目标 Stream 规则开启访问日志并重新应用。
- TCP 长连接只有关闭后才进入已结束会话统计。
- UDP 按 Nginx 会话统计，不等同于数据包数量。
- Stream 状态码与 HTTP 状态码不是同一套含义。
- 历史统计和近期样本的保留数量不同，样本不代表完整日志。

### 11.4 运行日志

**运行日志**可以查看：

- Nginx 错误日志。
- HTTP 访问日志。
- Stream 访问日志。
- nginx-web 管理服务日志。

默认读取最近一段日志。搜索只针对当前已加载内容，搜索期间暂停自动刷新；清除搜索后恢复。长行默认不换行，可以横向滚动，也可以开启自动换行。

排障时通常先看 Nginx 错误日志，再结合对应 HTTP 或 Stream 访问日志判断请求是否真正到达应用。

## 12. 草稿、校验、应用与回滚

nginx-web 将“编辑配置”和“让 Nginx 使用配置”分成两个阶段：

1. 创建、修改、停用或删除规则，形成草稿。
2. 点击 **校验配置**，在候选目录执行 `nginx -t`。
3. 点击 **保存并应用**，原子替换正式配置。
4. Nginx 已运行时进行平滑重载；未运行时尝试启动。
5. 启动或重载失败时，尝试恢复上一份有效配置。

“保存并应用”会应用**全部草稿**，不只应用当前页面的一条规则。执行前应检查其他页面是否还有未完成的修改。

每次成功应用都会生成配置历史。恢复历史或导入备份只会形成新草稿，需要检查并再次应用。也可以放弃全部未应用修改，回到 Nginx 当前使用的配置。

## 13. 备份、恢复与迁移

### 13.1 备份包含的内容

JSON 备份包含当前已保存的：

- 全局设置。
- HTTP(S) 与 TCP/UDP 规则。
- HTTP(S) 规则分组。
- HTTP 与 Stream 转发服务组。
- 限流策略。
- 证书和私钥。
- 自定义 Nginx 配置。
- 尚未应用的草稿。

备份含明文私钥，请将其视为敏感文件，不要发送到公开 Issue、聊天群或不受信任的网盘。

### 13.2 备份不包含的内容

- 运行日志和流量统计。
- 代理缓存。
- 配置历史。
- ACME 账户、DNS 凭据和自动续期任务。
- 自定义配置引用的外部文件。

### 13.3 恢复与迁移步骤

1. 在旧设备下载 JSON 备份，并另行复制外部依赖文件。
2. 在新设备安装相同或兼容的新版本 nginx-web。
3. 打开 **备份与恢复**，选择备份文件。
4. 核对导入摘要，确认恢复为草稿。
5. 修改因设备变化而失效的 IP、目录和端口。
6. 校验并应用配置。
7. 为需要自动续期的证书重新建立 ACME 任务和 DNS 凭据。

恢复不会直接覆盖正在运行的配置。不同证书材料会创建新副本并更新草稿引用，检查无误后再应用。

## 14. 全局设置与自定义配置

### 14.1 全局设置

全局设置包括：

- 默认 HTTP/HTTPS 高位端口和配置历史保留数量。
- Worker、连接数、文件句柄、Multi Accept、AIO 和线程池。
- Real IP Header、可信代理网段及递归解析。
- Gzip、TLS 协议、加密套件、会话和客户端证书校验。
- 访问日志、错误日志、自定义日志格式、缓冲与轮转。
- Map、Geo、Split Clients 等动态变量。
- 清理应用自身的 HTTP 代理缓存。

修改全局设置会影响多个规则。不了解 Worker、文件句柄、TLS 或 Real IP 参数时，建议保留默认值。Real IP 配置错误可能导致日志和限流使用错误的客户端地址。

### 14.2 Nginx 配置页面

系统生成的 `nginx.conf` 和规则片段保持只读，可查看、复制和校验。高级用户可以创建：

- `custom-*.conf`：加载到 HTTP 配置范围。
- `custom-*.stream`：加载到 Stream 配置范围。

自定义配置会进入草稿、配置历史和备份，并与系统生成配置一起执行 `nginx -t`。它不受结构化表单的全部安全限制，仅应由熟悉 Nginx 上下文、变量和模块支持范围的管理员使用。

内置 Nginx 不包含 HTTP/3/QUIC、Brotli、Lua/OpenResty、JWT、headers-more、GeoIP2、ModSecurity/WAF、第三方主动健康检查或 Prometheus 模块。不要在自定义配置中使用未编译模块的指令。

## 15. 安全与权限说明

- 管理界面要求 fnOS 管理员身份，变更请求还会校验专用请求标识。
- 管理服务和内置 Nginx 均以普通 `nginx-web` package 用户运行，不申请 root 权限。
- 应用只使用自己的安装、配置、数据和临时目录，不操作飞牛系统 Nginx。
- 证书私钥不会通过普通 API 返回浏览器；应用目录中的证书和 ACME 文件使用受限权限保存。
- ACME 自动续期所需 DNS 凭据会保存在应用私有数据目录中，因此 NAS 管理账号和磁盘数据同样需要妥善保护。
- 自定义配置可以引用外部文件，但应用用户必须拥有相应权限；不要为了方便把敏感文件设置成全局可读写。
- 备份文件包含私钥，日志可能包含域名、客户端地址或业务路径，分享前必须脱敏。

## 16. 常见故障排查

建议按以下顺序排查：

```text
转发服务可达 → 配置是否已应用 → 端口是否监听 → DNS → 防火墙/映射
             → TLS 证书 → HTTP/Stream 日志 → 后端响应
```

| 现象 | 检查方向 |
| --- | --- |
| 页面显示待应用 | 点击校验并保存应用；注意会同时应用其他草稿 |
| Nginx 启动失败 | 查看 Nginx 错误日志，检查端口占用、自定义指令、外部文件权限和证书路径 |
| 连接超时 | 检查 DNS、访问端口、监听类型、防火墙、路由器映射及公网入口 |
| 连接被拒绝 | 确认 Nginx 正在运行、端口已应用且没有被其他程序占用 |
| 返回 404 或错误站点 | 核对客户端实际 Host、端口、协议、默认站点和 Location 匹配 |
| 返回 502 | 从 NAS 检查后端地址、端口、协议和服务状态，并查看错误日志 |
| 返回 504 | 检查后端响应速度、网络连通性和读取/连接超时 |
| 浏览器提示证书不安全 | 检查实际收到的证书 SAN、有效期、证书链、域名解析和规则所选证书 |
| IPv4 正常、IPv6 失败 | 检查 AAAA、客户端 IPv6、规则监听类型、IPv6 入站防火墙及分组继承 |
| 没有请求统计 | 确认已应用统计配置、访问日志开启且请求已经结束；长连接不会提前计数 |
| TCP/UDP 没有会话统计 | 为规则开启 Stream 访问日志并应用；等待会话结束后再查看 |
| 静态文件返回 403 | 在飞牛应用设置中确认该目录已授权，并检查目录和父目录权限，确认 `nginx-web` 用户可以访问 |
| 80/443 启动失败 | 当前版本不支持普通用户直接监听低端口，请使用高位端口映射 |
| ACME 申请失败 | 检查 DNS 服务商、凭据权限、Zone、网络、传播时间及 CA 错误信息 |
| 修改证书后仍显示旧证书 | 确认签发与部署完成、规则引用正确、DNS 指向正确设备，再重新建立连接验证 |

不要只根据浏览器的一句错误提示判断唯一原因。优先查看应用状态和日志，并使用客户端实际访问的域名、协议与端口复现。

## 17. 问题反馈

提交问题时建议提供：

- nginx-web 版本。
- fnOS 版本和设备 CPU 架构。
- 内网或外网、IPv4 或 IPv6。
- 完整的复现步骤、预期结果和实际结果。
- 客户端访问的协议与端口。
- 浏览器错误、HTTP 状态码或客户端报错。
- 脱敏后的 Nginx 错误日志、访问日志或管理服务日志。
- 必要的页面截图。

请勿上传：

- 证书私钥。
- DNS API Token、Secret 或云账号凭据。
- 未脱敏的完整备份。
- 含敏感 Cookie、Authorization、内网拓扑或个人信息的日志。

项目地址与问题反馈入口见 [GitHub 仓库](https://github.com/chenpingonline/nginx-web-fnos)。
